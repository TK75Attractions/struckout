# 2026-10-14 の 2 台接続テストのメモ

スマホ 2 台 (120fps と 30fps) をカメラアプリから ball_tracker に USB (adb reverse) でつなぎ、
実際にボールを投げて着弾が出るかを試した。動画は撮っていないので、着弾の正解はない。

## 構成

| | Pixel 9 (`49190DLAQ00201`) | OPPO CPH2639 (`MZH649AUOREYBUN7`) |
|---|---|---|
| アプリ | `com.taichi765.struckoutCameraApp.highspeed` (`app_variant: highspeed`) | `com.taichi765.struckoutCameraApp` (`app_variant: camerax`) |
| フレームレート | 120fps | 30fps |
| 画像 | 640×360、焦点距離 447.67px | 640×480、焦点距離 504.31px |
| 行ごとの露光のずれ (上端と下端) | 4.543ms | 26.112ms |
| 露光時間 | 5.3〜8.3ms | 30〜50ms |
| 位置 x, y, z (m) | 0.075, 1.08, 1.259 | 0.075, 0.12, 1.259 |
| 回転 x, y, z (度) | 134.11, -1.06, -150.11 | 135.39, 0.25, -33.77 |

- ball_tracker: `target/release/ball_tracker.exe --input network --output csv -j`。
  バイナリは 10/12 19:45 のビルド (ブランチ `feature/camera-kyv45-support`)。
- 時刻合わせ: 2 台とも `synced=true` (`timestamp_source=Realtime`)、往復 2〜5ms。
  撮影から受信までの最短は Pixel が 62ms、OPPO が 84ms (1222 の回)。

## 気づいたこと

- **ball_tracker の CSV に改行が入らない。** `ball_tracker/src/collision_output/csv.rs` が `"{},{},{}"` を
  `\n` なしで書くので、点がつながって 1 行になる (`2.1130140832677350,...` は z = 2.113014083267735 の
  あとに次の x = 0 が続いたもの)。分析には `collisions_1222.csv` を使う。
- **ボールを投げていないあいだも、2 台ともフレームを送り続けていた。** アプリは何かを検出したフレームしか
  送らない。1222 の回の最初のフレーム (Pixel) の検出は 262×80px で画像の下のほう (image_y 0.89) にあり、
  ボールにしては大きい。背景などを拾っている可能性がある。
- アプリの設定画面のラジオボタンは、保存されている値に関係なく「Network」が選ばれた表示で始まる
  (`ConfigScreen.kt` の `mutableStateOf(radioOptions[0])`)。押し直さずに保存すると Local のまま変わらない。
  Pixel はこのせいで一度つながらなかった。
- ball_tracker との接続が切れると、アプリが落ちる (12:05、12:20、12:21、12:35 に計 5 回)。USB を挿し直したり
  ball_tracker を再起動したりしたら、`adb reverse` を設定し直し、アプリも開き直す必要があった。
- 不具合と直すべき点は `issues.md` にまとめた。
- ball_tracker が書いている最中の CSV と JSON は、エクスプローラーなどでは 0 バイトに見える
  (開いたままのファイルのサイズの表示が更新されないため)。中身は書かれている。
